# Quant Finance Project KOR

한국 주식(코스피·코스닥) 전용 예측·검증 프로그램입니다. 미국·글로벌 버전은 [Quant_Finance_Project](https://github.com/Hyeonwoo01/Quant_Finance_Project)입니다.
모든 예측은 **그 시점까지의 데이터로만 학습하는 워크포워드 방식**으로 검증하고, 검증 결과를 화면에 함께 보여줍니다.
분석·검증용 도구이며 주문을 내는 실거래 시스템이 아닙니다 ([범위와 한계](#범위와-한계)).
각 모델의 수식·쉬운 풀이·검증 방법은 **[MODELS.md](MODELS.md)** 에 정리했습니다.

## 기능

| 탭 | 내용 |
|---|---|
| 주가 예측 범위 | t분포 GARCH 시뮬레이션으로 향후 68%·95% 가격 범위, 손실 위험(VaR·ES, 모델 vs 과거 실제). 변동성 모델: 대칭 GARCH / 비대칭 GJR-GARCH / 자동(AIC) |
| 방향 예측 | 가격·거시(환율·코스닥·전날 미국 시장·한국은행 금리)·실적·외국인/기관 수급·DART 공시 특징 + 여러 모델 자동 선택(과거 상승 비율보다 낫지 않으면 그 비율 사용), 가정 바꿔 점검, 12개 조합 착시 보정(Deflated Sharpe), 수익 분해(타이밍 실력 vs 노출, 한국판 5요인) |
| 코스피 종목 고르기 | 코스피 약 200종목 상대 순위 (모멘텀·저변동성·수급·실적·자사주·가치), 상장폐지 종목 포함(KRX), 알려진 요인(시장·모멘텀·저변동성·소형·가치)으로 설명되는지 회귀, 같은 조건의 기준 전략(모멘텀·저변동성·가치 단일) 비교, 모델 비교표 착시 보정, 운용 규모별 시장 충격 비용, 비용·슬리피지 민감도와 손익분기 비용, 위험 반영 비중(변동성 역가중), 시장 하락·횡보·상승 구간별 성과, 지금 고른 종목들의 VaR·최악의 날·시장 급락일 손실. GitHub Actions가 매주 계산해 두어 배포된 앱에서 바로 보이고, 그 주의 추천을 미리 적어 두었다가 채점(실전 기록) |
| 수급·공시·뉴스 | 네이버 증권 실적·전망치, DART 공시, 외국인·기관 수급, 뉴스 감성 |
| 변동성 | 실제 변동성과 GARCH 추정·예측, 계수와 꼬리 두께(ν), 대칭 GARCH vs GJR-GARCH 비교(γ·AIC) |
| 시장 국면 | 2상태 국면 전환 모델(안정/불안), '불안 국면엔 현금' 전략 vs 단순 보유, 수익 분해(한국판 5요인 포함) |
| 예측 정확도 검증 | **실전 기록**(매일 미리 적어 둔 예측을 21거래일 뒤 채점), GARCH vs 단순 예측의 과거 오차, 범위 적중률, 하루 VaR 예외 검정(Kupiec·Christoffersen), 대칭 vs GJR 과거 예측 오차 |

**기능마다 답하는 질문이 다릅니다** — 서로 연결되지만 같은 지표로 검증할 수 없어 따로 채점합니다.

| 기능 | 답하는 질문 | 아닌 것 | 채점 |
|---|---|---|---|
| 방향 예측 | h일 뒤 오를 확률은? | 수익의 크기 (확률 구간별 실제 수익 표를 따로 봄) | 적중률·Brier·AUC·겹침 보정 z |
| 주가 예측 범위 | h일 뒤 가격이 얼마나 흩어질 수 있나? | 기대 가격·방향 (중심은 현재가, 평균 0 가정) | 범위 적중률, GARCH 오차 |
| VaR·ES | 정한 확률에서 손실이 얼마까지 날 수 있나? | 손실이 날지 여부 | Kupiec·Christoffersen, ES 검정 |
| 매매 전략 (방향·국면·종목 고르기) | 비용·세금 뒤 단순 보유보다 나은가? | 예측 정확도 | 초과수익 신뢰구간, 자기상관 보정 t값, DSR |

## 한국 시장에 맞춘 점

- **종목:** 코스피·코스닥 주식과 ETF, 지수(코스피 ^KS11 · 코스닥 ^KQ11 · 코스피200 ^KS200)만 다룹니다. 한글 이름이나 6자리 코드로 검색합니다.
  코스피200은 Yahoo에 과거 기록이 거의 없어 네이버 차트에서 받습니다 (코스피·코스닥 지수도 Yahoo 기록이 너무 짧으면 네이버로).
- **증권거래세:** 백테스트에서 **팔 때만**, 거래한 날짜의 세율로 뺍니다. ETF는 면제, 지수는 직접 사고팔 수 없어 세금 없이 계산합니다.
  수수료·체결 비용(살 때·팔 때 각각)은 사이드바에서 따로 정합니다. 세율이 바뀌면 `kr_costs.py`의 표에 한 줄만 추가하면 됩니다.

  | 시행 | 코스피 (거래세 + 농어촌특별세) | 코스닥 |
  |---|---|---|
  | ~2019-05 | 0.30% | 0.30% |
  | 2019-05-30 | 0.25% | 0.25% |
  | 2021 | 0.23% | 0.23% |
  | 2023 | 0.20% | 0.20% |
  | 2024 | 0.18% | 0.18% |
  | 2025 | 0.15% | 0.15% |
  | 2026 | 0.20% | 0.20% (2025년 세법 개정 기준) |

- **거시 지표 시차:** 한국 장(15:30)이 같은 날짜 미국 장보다 먼저 끝나므로, 방향 예측의 거시 지표는 **모두** 하루 늦춰 씁니다
  (미국 지표뿐 아니라 코스피·코스닥 지수, 환율, 한국은행 금리도 보수적으로 같이 늦춤).
- **한국판 요인 (파마-프렌치 대신):** 한국 시장 전용 무료 일간 요인 데이터가 없어, 매주 종목 고르기 작업이 같은 종목 범위
  (그때의 거래대금 상위 200)로 시장·소형주·가치·수익성·모멘텀 일간 요인을 직접 만들어 `ranking/kr_factors.csv`에 저장합니다.
  방향 예측·시장 국면의 수익 분해에 쓰고, 코스피 종목 고르기 탭에서 요인별 성과를 볼 수 있습니다 (투자 요인 CMA는 자산 데이터가 없어 뺌).
- **아직 넣지 않은 것 (계획):**
  - 옵션 가격·변동성 매매 백테스트: 과거 옵션 시세(날짜·행사가별 가격, 내재변동성)와 VKOSPI가 Yahoo·네이버에 없어서 아직 못 넣었습니다.
    KRX Open API(옵션·주식옵션 일별매매정보, 파생상품지수 시세정보) 승인을 받았고, 코스피200과 개별주식옵션으로 추가할 예정입니다 ([다음 단계](#다음-단계-계획)).

## 실행

Windows: `run.bat` 더블클릭 (처음 실행 시 가상환경을 만들고 패키지를 설치합니다). **Python 3.12 이상**이 필요합니다 (3.12·3.13에서 확인).

직접 실행할 때 (Windows 명령 프롬프트):

```bat
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m streamlit run app.py
```

macOS·Linux:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m streamlit run app.py
```

### API 키 (권장)

한국 종목의 DART 공시·재무제표와 한국은행 금리를 쓰려면 키가 필요합니다. [OpenDART](https://opendart.fss.or.kr)와
[한국은행 ECOS](https://ecos.bok.or.kr/api/)에서 무료로 발급됩니다. 없으면 그 데이터 없이 계산합니다.

- **내 PC:** `api_keys.env.example`을 `api_keys.env`로 복사해 키를 넣으세요 (`.gitignore`에 있어 저장소에 올라가지 않음).
- **Streamlit Cloud:** 앱 Settings → Secrets에 `DART_API_KEY = "..."`, `ECOS_API_KEY = "..."`.
- **GitHub Actions(실전 기록·매주 종목 고르기):** 저장소 Settings → Secrets and variables → Actions에 같은 이름으로.
- **`KRX_API_KEY` (선택):** [KRX Open API](https://openapi.krx.co.kr) 키. 매주 종목 고르기가 유가증권 일별매매정보로 상장폐지 종목과 그날의 시가총액을 씁니다
  (없으면 예전 방식). 데이터 연결 점검(`python forecast_log.py check`)에서 승인 여부와 해석 결과를 확인합니다. 옵션·VKOSPI는 아직 계산에 쓰지 않습니다.

키 값은 저장소에 들어가지 않습니다. `python forecast_log.py check`는 키가 실제로 불러지는지만 출력하고 키 값은 출력하지 않습니다.

### 코스피 종목 고르기 데이터

GitHub Actions(`ranking`)가 **매주 금요일 한국 시간 오후 6:17**에 데이터를 갱신하고, 앱 설정 조합(교체 주기 63·21거래일 × 체결 시점 × 증권거래세 켬/끔,
수수료 5bp)마다 탭에 보일 결과를 계산해 `ranking/results.pkl`로, 한국판 일간 요인을 `ranking/kr_factors.csv`로 커밋합니다. 그래서 배포된 앱은 데이터를 받지 않고 바로 결과를 보여 줍니다.
원본 시세·수급·재무는 저장소에 올리지 않고(재배포 방지) Actions 캐시에만 두어, 다음 실행은 새 날짜만 받습니다.
`KRX_API_KEY`가 있으면 KRX 유가증권 일별매매정보(그날 상장돼 있던 전 종목)를 날짜별로 받아(처음 약 1,500일, 이후엔 새 날짜만) 상장폐지 종목과 그날의 시가총액을 씁니다.

- **실전 기록:** 그 주의 추천(교체 주기 63거래일, 다음 날 종가 체결 기준 상위 20%)을 `ranking/picks.csv`에 **추가만** 하고,
  21·63거래일 뒤 바구니(동일 비중)와 그날 종목 범위 전체 평균의 수익률을 채점합니다 (비용 전). 탭의 '실전 기록'에 요약이 나옵니다.
- **바로 한 번 돌리기:** GitHub → Actions → ranking → Run workflow. 처음엔 6년치를 모두 받느라 몇 시간 걸릴 수 있고, 시간 안에 못 끝내도 받은 데이터는 캐시에 남아 다시 돌리면 이어서 받습니다. 그다음부터는 새 날짜만 받습니다.
- **코드가 바뀐 푸시:** 시총 상위 60종목·4년치(KRX는 최근 60거래일)로 전체 과정을 실제 데이터로 빠르게 점검만 합니다 (저장하지 않음).
- **수수료를 바꿔 직접 계산:** 탭의 '수수료를 바꿔 직접 계산하려면' → **데이터 받기**, 또는 `python universe.py update`
  (처음엔 6년치 수급·공시·재무를 받느라 1시간 안팎 — GitHub Actions에서 주가·수급만 약 1시간 걸렸습니다).
  이 컴퓨터에 데이터가 있으면 미리 계산된 결과 대신 직접 계산합니다.

### 실전 기록 (앞으로의 예측)

과거 검증은 결과를 이미 아는 데이터로 하므로 가정을 나중에 고를 여지가 남습니다. 그래서 GitHub Actions(`forecast-log`)가 평일마다
**한국 시간 오후 5:07**(장 마감 뒤 종가가 확정된 시각)에 그날의 예측을 `forecast_log/log.csv`에 **추가만** 하고 커밋합니다.
GitHub 예약 실행은 몇 시간 늦게 돌 때가 있지만(2026-10-23은 약 5시간), 장 마감 뒤라 기록에는 영향이 없습니다.
'예측 정확도 검증' 탭이 21거래일 뒤 실제 결과로 채점합니다 (방향·확률 정확도, 68%/95% 범위, GARCH 오차, 하루 VaR 예외, 뉴스 감성의 쓸모).

- **기록 종목:** `forecast_log/tickers.txt` — 코스피 지수, KODEX 200, KODEX 코스닥150, 코스피 시가총액 상위 20개(보통주), 상위 20에 없는 업종(인터넷·철강·화학·정유·전력·통신·소비재·해운·게임) 9개, 코스닥 3개(바이오·2차전지 소재·로봇) — 모두 35개. 한 줄 추가하면 다음 기록부터 포함됩니다.
- **바로 한 번 돌리기:** GitHub → Actions → forecast-log → Run workflow.
- 매일 21일 기간이 겹치므로, 의미 있는 결론에는 최소 몇 달, 가능하면 1년 이상이 필요합니다.
- GitHub Actions는 Claude 구독과 무관하게 GitHub 서버에서 돕니다 (공개 저장소는 무료).

## 검증: 계산이 맞는지 vs 돈이 되는지

두 질문은 따로 확인합니다. 코드가 정확해도 수익이 안 날 수 있고, 과거 백테스트에서 수익이 나도 앞으로 난다는 보장은 없습니다.

| 질문 | 어떻게 확인하나 | 어디서 보나 |
|---|---|---|
| **계산이 맞나** (미래 정보·시간축·비용) | `tests.py`가 푸시마다 Python 3.12·3.13에서 자동 실행. 미래 데이터를 바꿔도 과거 예측·요인 값이 그대로인지, 판단(t) → 체결(t+1 종가) → 수익(t+2부터)의 순서, 비용은 체결 뒤 첫 수익과 같은 날·세금은 판 날에만 체결일 세율로, 겹침 보정 t값·블록 부트스트랩 구간이 우연을 목표만큼만 '유의'로 잡는지(몬테카를로: 독립 자료와 GARCH·두꺼운 꼬리 수익률, 조건·결과는 [MODELS.md](MODELS.md#겹침-보정-t값-hansen-hodrick)) 등 | [Actions → tests](https://github.com/Hyeonwoo01/Quant_Finance_Project_KOR/actions/workflows/tests.yml) |
| **돈이 되나** (실제 데이터, 비용·세금 후) | `validation.py`가 매주 기록 종목마다 앱 기본 설정 그대로 워크포워드 검증: 방향 예측력(21일 예측을 21일 결과로), 방향·국면 전략 vs 단순 보유(연 수익률·샤프·최대 낙폭, 초과수익의 블록 부트스트랩 95% 신뢰구간, 가정 바꿔 통과 수, DSR), 21일 분할 보유 전략, 확률 구간별 실제 수익, 하루 VaR·ES 검정, 코스피 종목 고르기(손익분기 비용·위험 반영 비중·시장 구간별·기준 전략) | [validation/README.md](validation/README.md) |
| **앞으로도 맞나** (손대지 않은 표본) | 매일·매주 예측을 미리 적어 두고 나중에 채점 (모델 선택·튜닝에 쓰지 않는 기록) | 예측 정확도 검증 탭, 코스피 종목 고르기 탭의 실전 기록 |

- **시간축:** 방향 예측의 채점(21거래일 방향 vs 21거래일 뒤 결과)과 방향 전략의 수익(매일 다시 판단해 다음 하루를 들고 있음)은
  서로 다른 질문이라 따로 보고합니다. 예측력이 없어도 전략 수익이 날 수 있고(대부분 보유한 덕분), 그 반대도 있습니다.
  21일 예측을 그 기간 그대로 매매에 쓰면 어떤지는 '21일 분할 보유' 전략(매일 자본의 1/21을 사서 21거래일 보유)으로 따로 잽니다.
- **판정:** 전략의 경제적 가치는 비용 뒤 일간 초과수익(전략 − 단순 보유)의 95% 신뢰구간 하한이 0보다 클 때만 '있음'으로 봅니다.
  샤프 비율 하나로 판정하지 않습니다.

### 지금까지의 결과 (2026-10-26, 기록 종목 35개 + 코스피 종목 고르기)

최신 숫자는 매주 자동으로 갱신되는 [validation/README.md](validation/README.md)에 있습니다. 아래는 2026-10-26 실행(코드 d1ba9a5) 요약입니다
(방향·국면은 2019-12 ~ 2026-10 워크포워드, 상장이 짧은 종목은 더 짧음).

| 질문 | 결과 |
|---|---|
| 방향 예측이 '과거 상승 비율'보다 나은가 (21거래일) | **35종목 중 0종목.** 겹침 보정 z는 −1.9 ~ +1.2, 확률 정확도는 모든 종목에서 과거 상승 비율보다 나쁨 |
| 예측 확률이 맞나 (전 종목 합산) | **아니오.** 상승 확률을 60% 넘게 낸 날의 실제 상승 비율은 48%, 40% 아래로 낸 날은 55% — 확률 구간과 상관없이 평균 21일 수익은 +2~3%로 비슷 |
| 방향 전략이 비용·세금 뒤 단순 보유보다 나은가 | **0 / 35** (매일 판단), **0 / 35** (21일 분할 보유). 초과수익 95% 신뢰구간 하한이 0을 넘은 종목 없음 |
| '불안 국면엔 현금' 전략 | **0 / 35.** 낙폭을 줄인 종목은 있지만 수익을 더 많이 잃음 |
| 하루 VaR·ES가 손실 위험을 맞게 잡나 (첫 3년 뒤 전체 약 1,700일) | VaR **20 / 35 통과**, ES **32 / 35 통과.** 코스피 지수·KODEX 200은 VaR·ES 모두 위험을 작게 잡음 (95% VaR를 넘은 날 약 7%, 목표 5%). 기각된 개별 종목은 대부분 99% VaR의 예외가 몰려 나온 경우 |
| 코스피 종목 고르기 (상장폐지 58종목 포함, 교체 63거래일) | 비용·세금 후 초과수익 **연 +12.9% (t 2.3)**, 순위 정확도 IC 0.20 (t 6.1), 손익분기 비용 매수·매도 각각 약 264bp. 다만 **알려진 요인을 빼면 알파가 −4.4%(t −0.3)로 0과 구분되지 않고**, 같은 조건의 **모멘텀 단일 기준 전략이 +16.9%로 더 높음**. 리밸런싱이 11번뿐이라 확신하기 어려움 |

**결론:** 한 종목의 방향을 맞히는 신호는 확인되지 않았습니다. 코스피 종목 고르기는 순위를 실제로 맞히지만(IC 유의), 그 초과수익은
모멘텀·저변동성·가치 같은 이미 알려진 요인으로 설명되고 단순 모멘텀보다 낫지 않습니다 — 새로운 알파가 아니라 요인 투자에 가깝습니다.
오늘 고친 상장폐지 포함·정답 결측·시간축 정렬만으로 같은 설정의 초과수익이 +20%에서 +12.9%로 줄었습니다(예전 숫자가 그만큼 부풀려져 있었음).
이 프로그램의 가치는 수익 증명이 아니라, 그런 주장을 미래 정보·시간축·비용·과적합 착시 없이 검증하는 도구라는 데 있습니다.
앞으로의 판단은 미리 적어 두는 실전 기록(매일 예측 35종목, 매주 종목 고르기 추천)으로 합니다.

## 백테스트 가정

| 항목 | 가정 |
|---|---|
| 체결 시점 | t일 종가까지 보고 판단 → **다음 거래일 종가에 체결** (기본). 사이드바에서 '신호 낸 날 종가(낙관적)'로 바꿔 비교 가능 |
| 비용 | 사고팔 때 각각 수수료·체결 비용(bp) + 팔 때 증권거래세(실제로 파는 날의 세율). 비용은 체결 뒤 첫 수익과 같은 날에 뺌 |
| 미래 정보 차단 | 모든 모델은 판단 시점까지의 데이터로만 학습·선택. `tests.py`가 미래 데이터를 바꿔도 과거 예측이 그대로인지 확인 |
| 겹치는 예측 기간 | h일 예측을 매일 하면 정답이 겹침 → z는 Hansen-Hodrick 표준오차(시차 h−1) |
| 과적합 보정 | 여러 설정 중 1등의 착시를 Deflated Sharpe로 보정 (수익률 자기상관만큼 표본을 줄여 셈). 코드 밖에서 사람이 바꿔 본 것은 보정되지 않아, 기본 설정을 고정하고 실전 기록으로 판단 ([EXPERIMENTS.md](EXPERIMENTS.md)) |
| VaR 검증 | 하루 VaR(95%·99%)를 Kupiec·Christoffersen 검정 |
| GARCH 추정 | 시작값 3개로 최적화, 모두 실패하면 기본값으로 대체하고 화면에 경고 |
| 변동성 모델 | 대칭 GARCH(1,1) 또는 GJR-GARCH(하락한 날 충격 반응이 α+γ). '자동'은 두 모델의 AIC로 고름. 실전 기록도 자동 |
| 시장 충격 (코스피 종목 고르기) | 한 번 사거나 팔 때 추가 비용 ≈ 하루 변동성 × √(주문 금액 ÷ 하루 거래대금), 계수 1(보수적). 종목당 주문 = 자본 ÷ 보유 종목 수, 거래대금은 63일 평균 |
| 재현 정보 | 화면 아래에 코드 커밋과 데이터 지문(기간·길이·값 해시)을 표시하고, 실전 기록에도 데이터 지문을 저장 — 결과가 달라지면 데이터가 바뀐 건지 코드가 바뀐 건지 구분 |

## 범위와 한계

- **실거래 시스템이 아닙니다.** 주문 실행, 증권사 연동, 킬 스위치, 포지션·손실 한도 같은 기능이 없습니다.
- **체결:** 종가에 원하는 수량이 체결된다고 가정합니다. 가격제한폭(하한가면 못 팔고 상한가면 못 삼)과 거래정지는 반영하고, 시장 충격은 코스피 종목 고르기에서
  운용 규모별로 제곱근 법칙으로 근사합니다. 호가 공백과 종가 동시호가에서 실제로 체결 가능한 수량은 반영하지 않고, 다음 날 시가 체결은 계산하지 않습니다
  (대신 비용·슬리피지를 0~40bp로 바꿔 본 민감도와 손익분기 비용을 보여 줌).
- **코스피 종목 범위:** 과거 시점마다 그때의 거래대금 상위 200개입니다. KRX 일별매매정보(그날 상장돼 있던 전 종목)로 그 사이 **상장폐지된 종목도 포함**하고,
  폐지 종목은 정리매매 마지막 가격까지의 손익을 반영한 뒤 현금으로 봅니다. 시가총액(가치 지표·한국판 요인)은 **그날의 실제 값**을 씁니다.
  남은 한계: 폐지 종목은 수급·실적·재무 데이터가 없어 그 신호를 중간값으로 두고, 정리매매 없이 거래정지된 채 폐지된 종목은 마지막 거래 가격으로 계산합니다
  (실제 회수액은 더 낮을 수 있음). KRX 데이터를 받지 못한 날·종목은 예전 방식(현재 상장 종목, 그날 주가 × 현재 상장주식수)으로 대신합니다.
  종목 고르기는 **코스피만** 대상입니다(코스닥 미포함). 비중은 동일 비중이 기본이고 변동성 역가중을 비교로 보여 주지만,
  업종·베타 제한이나 종목 간 상관을 고려한 최적화는 하지 않으며 요인 노출은 회귀로 보고만 합니다.
- **재현성:** 결과마다 코드 커밋과 데이터 지문(기간·길이·값 해시)을 남기고, 실전 기록(예측·추천)은 그때의 값으로 저장해 나중에 다시 계산하지 않고 채점합니다.
  다만 원본 시세·수급·재무 자료는 재배포 문제로 저장소에 올리지 않고 GitHub Actions 캐시(7일 쓰지 않으면 삭제)에만 둡니다.
  그래서 데이터 공급처가 과거 값을 고치면, 지문으로 바뀐 것은 알 수 있지만 옛 숫자를 똑같이 다시 만들 수는 없습니다.
- **데이터 출처:** Yahoo Finance(주가·실적 서프라이즈), 네이버 증권 비공식 API(종목 목록·수급·뉴스·실적 표·코스피200 차트), DART, 한국은행 ECOS.
  무료 데이터는 예고 없이 바뀌거나 지연·누락될 수 있습니다.
- **통계:** 여러 가정을 시험할수록 우연히 좋은 결과가 나올 가능성은 남습니다. 결론은 '가정을 바꿔도 유지되는지'와 실전 기록으로 판단합니다.
